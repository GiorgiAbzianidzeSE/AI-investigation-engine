# AI usage

> Draft written during implementation. Review and adjust it so it matches your own process before submitting.

## Tools

| Tool | Used for |
|---|---|
| Claude (chat) | Turning the task brief into the implementation specs in `specs/` (scope, architecture, corpus design, eval plan). |
| Cursor (agent) | Implementing the specs step by step: modules, tests, corpus generator, eval harness, Dockerfile, docs. |

## Generated vs written or changed by hand

- **Specs**: AI-drafted from the brief, then reviewed and edited by hand (scope cuts, stack choices).
- **Code**: generated by the Cursor agent from the specs, one build step per commit, then reviewed.
- **Ranker formula**: the spec defined the starting formula. The eval showed it was worse than plain RRF, and the
  formula was changed (min-max RRF, rarity-weighted bridge, half credit for body matches). See EVALUATION.md §4.
- **Eval question set**: the 28 incident questions and gold labels were designed with the corpus (Appendix B).
  The 14 HotpotQA questions are a seeded sample, not hand-picked.
- **Incident corpus text** (`scripts/incident_texts.py`): AI-written to the fact table in Appendix A. Guard tests
  check that contradictions are planted and the gaps stay open.

## Mistakes the AI made that were caught

- `QdrantStore.get_chunks` read `.score` from scroll results, which have no score. Caught by a test against
  qdrant-client's in-memory mode.
- `uv` picked Python 3.15, for which `onnxruntime` has no wheels. Pinned 3.11 (`.python-version`).
- `doc_type` guessing matched "change" before "changelog", and "incident" in "Finance Summary - Incidents".
  Caught by inspecting the parsed corpus; the keyword order was fixed.
- The first PDF parser lost all headings and paragraph breaks, so chunking B on PDFs was no better than A.
  Fixed by reading font weight and size and line gaps from `pypdf`.
- The ranker as first written made retrieval worse (EVALUATION.md §4, items 1–3).
- The corpus-guard test flagged "euro" inside "European" (a false positive). Switched to whole-word matching.

## What was verified by hand, and how

- 72 unit tests (`uv run pytest -q`), with no network: fakes for the store, embedder and LLM, plus
  qdrant-client in-memory mode for the real store.
- Parsed every generated incident file and read the extracted text and chunk boundaries.
- Ran the dedup demo end to end against the running API: duplicate, near-duplicate, replace → version 2, delete.
- Read the per-question rankings behind each retrieval metric before and after the ranker changes.
